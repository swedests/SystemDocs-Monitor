# 🛡️ SystemDocs Monitor

Набор аппаратных оповещений и памяток, чтобы домашние пользователи знали, как безопасно обращаться с настроенным ПК, пока владелец в армии.

## ✨ Что умеет проект
- HWiNFO проверяет датчики и пороги, настроенные вручную для каждого оповещения.
- При срабатывании запускается AutoHotkey-скрипт с аргументом алерта и открывает подходящую инструкцию.
- Напоминает о чистке корпуса через 45/60/75 дней.
- Ведёт журналы и файл состояния мониторинга.

**Статус проверки:** 19.11.2026 выполнен реальный тест на ПК с HWiNFO64 8.52 — настроенные тревоги с запуском программы и открытием памяток работают.

## 📦 Что понадобится
- **Windows 10/11**
- **HWiNFO64** — [скачать с официального сайта](https://www.hwinfo.com/download/). Бесплатна для личного и некоммерческого использования; коммерческое использование HWiNFO64 требует Pro-лицензии. Владелец проекта использует версию **8.52**; более старые версии могут подойти, но не проверялись.
- **AutoHotkey v1.1.33 или новее в линейке v1** — [скачать с официального сайта](https://www.autohotkey.com/download/1.1/). Проверено на версии **1.1.37.02**. Проект не содержит исполняемый файл AutoHotkey: используется установленная версия из Windows.
- **MarkView** — [скачать с сайта MarkView](https://markview.io/). Бесплатный просмотрщик Markdown. Если он установлен не в `%LOCALAPPDATA%\MarkView\markview.exe`, укажи фактический путь в `ViewerPath`.

## ⚙️ Как работает тревога

**Датчик → порог HWiNFO → `alert.ahk` + аргумент → инструкция в MarkView**

Например, при тревоге процессора HWiNFO запускает `scripts\alert.ahk` с аргументом `cpu`. Скрипт записывает событие и открывает `config\alerts\ALERT_CPU.md`.

> **Важно:** проект не задаёт пороги за тебя. Уведомления создаются в HWiNFO вручную — для каждого нужного датчика отдельно.

## 🔔 Как настроить порог и запуск памятки в HWiNFO

1. Открой HWiNFO в режиме **Sensors-only** и найди нужный датчик в списке.
2. Открой настройки уведомлений датчика и включи **Enable alert**.
3. Выбери условие и введи порог. Для перегрева обычно задают верхнюю границу (`>=`), для низкого напряжения/оборотов или остатка ресурса — нижнюю (`<=`). Точный порог выбирай по документации компонента и фактическим показаниям.
4. Включи действие **Run a program** (в некоторых переводах — «Запустить программу»).
5. В поле программы укажи полный путь к `scripts\alert.ahk`, например `"<путь-к-проекту>\scripts\alert.ahk"`.
6. В поле аргумента укажи соответствующий короткий тип из [шпаргалки](docs/CheatSheet.md), например `cpu`, `v12` или `wear`. Не подставляй `%v` или `%s`: скрипт выбирает памятку по типу алерта. Ассоциация Windows запускает установленный AutoHotkey UX; директива `#Requires AutoHotkey v1.1.33+` в скриптах направляет их в совместимую версию v1 даже при установленной v2.
7. Настрой интервал/повтор оповещения по необходимости и сохрани параметры.
8. Повтори для каждого датчика, который требуется контролировать. Для безопасной проверки временно задай порог, который сработает при текущем показании датчика: для `>=` — ниже текущего значения, для `<=` — выше. Проверь, что открылась нужная памятка, и сразу верни рабочий порог.

Оставь HWiNFO запущенным. Если оно закрыто или для датчика не настроено уведомление с запуском программы, этот проект не получит тревогу. Подробная таблица аргументов и файлов инструкций — в [шпаргалке](docs/CheatSheet.md).

## 🧩 Для какой сборки настраивались датчики

- Накопитель: KingSpec NE, M.2 NVMe, 512 ГБ.

Датчики и их названия зависят от оборудования и версии HWiNFO. На другом ПК сопоставь датчики заново и проверь пороги: значения в шпаргалке — настройки этой сборки, а не универсальная рекомендация.

## 🚀 Установка и настройка проекта

1. Установи HWiNFO64, AutoHotkey v1.1 и MarkView.
2. Открой PowerShell от имени обычного пользователя и запустите установщик:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1"
```

При запросе Windows нажми «Да». Установщик попросит имя владельца в нужных падежах, сообщение об отсутствии, телефон и, если не найдёт MarkView автоматически, полный путь к нему.

Установщик создаёт `user_config.ahk`, ярлык автозапуска памятки, ярлык «Я почистил ПК» на рабочем столе и задания `Clean_Dust_Reminder`/`Clean_Mark_Task`.

Также устанавливается ярлык **«Проверить все тревоги»**. Он запускает тестовые памятки по очереди и не меняет пороги HWiNFO.

Перед установкой можно проверить поиск приложений без изменений в системе:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1" -WhatIf
```

3. Настрой уведомления HWiNFO по шагам выше.
4. Не публикуй `user_config.ahk`: он исключён через `.gitignore` и содержит личные данные.

Если запускать установщик повторно, он обновит конфигурацию и действия существующих ярлыков и задач.

### 🔍 Проверка зависимостей

Проверить установку HWiNFO64, MarkView, AutoHotkey v1 и конфигурации проекта можно командой:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1" -CheckDependencies
```

Команда ничего не изменяет в системе и выводит пометки `[OK]` или `[НЕТ]`.

### 🧪 Тестовая тревога

Для проверки маршрута памятки, не меняя пороги HWiNFO, запустите тест CPU-тревоги:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1" -TestAlert
```

Должно открыться окно `ALERT_CPU.md`. Настоящие датчики HWiNFO при этом не запускаются.

Проверить сразу все уникальные типы тестовых тревог можно так:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1" -TestAllAlerts
```

Установщик последовательно запускает их с интервалом в три секунды и открывает соответствующие памятки. Закройте окно после просмотра, чтобы следующее не осталось скрыто в очереди открытых окон.

### 🩺 Диагностика

Полную безопасную проверку проекта можно запустить командой:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1" -Diagnostics
```

Диагностик проверит приложения, конфигурацию, задания планировщика, кодировку `.ahk` и маршруты всех памяток. Краткий отчёт откроется в Блокноте и будет сохранён в `docs\diagnostics\report.txt`. Личные поля конфигурации в отчёте не выводятся.

### 🚀 Дополнительные команды

Запустить HWiNFO64, если он ещё не открыт:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1" -StartHWiNFO
```

Проверить системное сообщение Windows и дату последней чистки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1" -CheckCleaningNotice
```

Создать резервную копию `user_config.ahk` и папки `data` в `%USERPROFILE%\SystemDocs-Backups`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1" -Backup
```

Проверить наличие обновлений Git-репозитория с явным URL проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\setup.ps1" -CheckUpdates -Repository "https://github.com/OWNER/REPOSITORY.git"
```

Само обновление не применяется без явного режима `-UpdateProject`. Для клонирования вне Git-папки проект скачивается рядом с текущей копией без автоматического копирования личных данных.

### 🖥️ Показ памятки при входе в Windows

Установщик создаёт ярлык для [show_and_close.ahk](scripts/show_and_close.ahk) в папке автозагрузки текущего пользователя. При входе в Windows скрипт открывает памятку [docs/README.md](docs/README.md) в MarkView, разворачивает окно поверх остальных и через две минуты снимает режим «поверх всех».

Ярлык запускает установленный AutoHotkey и передаёт ему `.ahk` скрипт. Для работы нужны AutoHotkey v1.1 и MarkView. Не перемещай проект после установки: при переносе папки запусти установщик повторно.

Если не используешь установщик, альтернативно можно вручную создать ярлык в папке `shell:startup`, указав установленный `AutoHotkeyU64.exe` и аргументом `scripts\show_and_close.ahk`.

### ⏰ Ежедневная проверка чистки

Установщик создаёт задание **`Clean_Dust_Reminder`**, которое запускает установленный AutoHotkey v1.1 с файлом [cleaning_reminder.ahk](scripts/cleaning_reminder.ahk) каждый день в **12:00**. Скрипт вычисляет, сколько дней прошло с последней чистки, показывает напоминание при достижении 45, 60 и 75 дней и обновляет `data/status.txt`.

Задание запускается только при активном входе пользователя, чтобы окно напоминания было видно. Установщик автоматически подставляет фактический путь к AutoHotkey и проекту. Посмотреть или проверить задание можно так:

```cmd
schtasks /Query /TN "Clean_Dust_Reminder" /V /FO LIST
```

### ✅ Отметка выполненной чистки

После фактической чистки запусти на рабочем столе ярлык **«Я почистил ПК»**. Установщик создаёт его вместе с заданием **`Clean_Mark_Task`** и вызывает запуск этого задания через `schtasks`.

Задание запускает установленный AutoHotkey v1.1 с файлом `scripts\mark_cleaned.ahk` и настроено с наивысшим уровнем прав. Скрипт записывает текущую дату в `data/last_cleaning.txt`, обновляет журнал чисток и статус, а также системное сообщение Windows с датой чистки.

Не запускай ярлык, если ПК не чистили: он сбросит отсчёт и обновит дату последней чистки.

📝 Дата последней чистки хранится в `data/last_cleaning.txt`, это не журнал. Не удаляй этот файл вместе с логами: при его потере скрипт напомнит о чистке сразу.
